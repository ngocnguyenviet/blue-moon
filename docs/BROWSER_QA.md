# Browser QA

## Current evidence

QA was performed against the local seeded website at `http://localhost:3000` on 12 and 13 October 2026. The local DB contains fictional data. The 13 October checks used Playwright through the `mcp__node_repl__js` fallback because direct Playwright MCP tools were unavailable. Playwright was loaded from the existing Omniroute cache with Node `createRequire`, then launched against installed Chrome; no app dependency was installed or changed. Custom `web_tester` performed the initial and fresh-build checks; root completed the remaining OTP, Excel, stable mobile layout and PDF visual checks after the tester reached its usage limit. Browser screenshots and export artifacts are in `../artifacts/`. This report was finalized on 14 October; that morning `/api/health` still returned HTTP 200 with PostgreSQL connected.

### Passed

- Manager login and navigation to Hộ cư trú, Căn hộ, Khoản phải thu, Phiếu thu and Báo cáo. The charges list renders (994 results) without the earlier React crash. Households and apartments paginate; 30 apartments appear, with vacancies identified as Căn trống.
- Accountant login exposes resident/fee/payment/report functions while omitting manager-only Tài khoản and Nhật ký.
- Accountant recorded a partial 10,000₫ cash receipt for A0101 / Phí an ninh · 2026-09 with reference `QA-20261012-01`. The displayed debt dropped from 75,000₫ to 65,000₫. Receipt `BTWCEYL2` appeared as successful and dated 12/10/2026, and its receipt dialog showed payer, household, amount, method and date.
- Resident login displayed household A0101 / H001 and only its 36 fee records. Resident submitted a 5,000₫ local simulated payment; after selecting “Mô phỏng thành công”, it appeared in payment history as successful with method “Mô phỏng local”. No actual payment provider was contacted. The post-success fee balance was not rechecked.
- Manager received a fictional QA household `QA-1012-01` at vacant apartment A0603, using a `.local` email and fictional phone. The app displayed a generated temporary password once. Signing in with it led to the required password-change screen; after changing it, the account required email verification. No external email/SMS was sent.
- Report “Xuất Excel” downloaded `.playwright-mcp/BlueMoon.xlsx` (192,180 bytes).
- At 390, 768 and 1440 CSS-pixel widths, the report page heading stayed visible and the document did not overflow horizontally. Screenshots: [390px](../artifacts/qa-report-390.png), [768px](../artifacts/qa-report-768.png), [1440px](../artifacts/qa-report-1440.png). ### Unverified or incomplete

- The UI's “In / Lưu PDF” action itself opens the browser print flow, which is not automated here. The PDF artifact above was generated with Playwright `page.pdf` while the receipt view was open; physical printer/native print-dialog behavior remains unverified.
- Duplicate protection was checked in the browser by returning to payment history and reloading after one successful simulation; the receipt remained singular and the fee balance reflected one 1,000₫ allocation. Repeated signed provider callbacks were tested separately by the local API integration suite, not through a real VNPAY merchant account.
- True Gmail delivery and VNPAY Sandbox could not be checked because external accounts/provider credentials are not configured.

### Issues observed

- On the first pre-fix build (11 October), manager navigation to Khoản phải thu blanked the page with `TypeError: Cannot read properties of undefined (reading 'code')`. It rendered on both the 12 October QA build and the 13 October compiled build; the latest manager navigation had no `pageerror`.
- Initial unauthenticated page load emitted two console 401 responses for `/api/v1/auth/me`. No user-visible login failure was observed. No page errors were observed in the latest tested manager or resident flows.
- An earlier fresh-build Excel download wait timed out; the supplemental check downloaded the workbook successfully. No reproducible application defect remained from that timeout. The mobile screenshot captured mid-transition was replaced as evidence by a stable-state capture; no source change was needed.
